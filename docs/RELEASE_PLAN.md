# Have Disk release plan

The end-user deliverable is the signed mini ZIP, its matching source ZIP and SHA-256 checksums. The tester channel uses explicit local trust. An ordinary public release requires a publicly trusted signature.

1. **Validate the exact tester ZIP.** Record its digest, signer, source commit and Windows build. Rehearse installation through the INF in an isolated VM, check file output and account for removal leftovers. Repeat acceptance when the payload or signing identity changes. [VM procedure](VM_TESTING.md)
2. **Complete physical printing acceptance after hardware repair.** The exact Benteveo tester ZIP passed A4 application printing, copies/collation, paper-out, front-cover recovery and five cold cycles on build 26300.9974 after the solenoid repair. The signed 0.1.2 retry fix passed a timed USB interruption and follow-up on November 16. Retain the 30-second retry-window limitation; sleep/wake requires a host with standby support. Physical Letter remains deferred. Record page emergence, queue state and printer completion for controlled copies/collation and recovery tests. Exercise the Have Disk package on a clean physical target with a private recovery backup. Use complete removal and a fresh Have Disk installation when replacing an installed version. [Physical and recovery matrix](RELEASE_ACCEPTANCE.md)
3. **Define publication scope.** Start with the tested Windows edition/build, one original USB printer, A4 and the applications covered by evidence. Require physical Letter evidence before advertising Letter. Office is deferred. [Test status](TEST_STATUS.md)
4. **Publish only after review.** For a tester build, distribute the certificate identity independently and explain removal and expiry. For ordinary users, obtain trusted signing, verify the complete catalog on a clean machine and repeat installation without adding tester trust. Review the guide, license, matching source and checksums for the exact ZIP before tagging a release.
